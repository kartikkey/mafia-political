# RCA — deep-state-game initial deploy failure

## Symptom
Initial deploy never gets past the `pull_source` (build-context prep) step. Two runs failed identically:
- Run `956fa7f4-796f-4d35-9dae-d15c0c7ba874` (original)
- Run `a216c135-d976-4661-8a2a-11a4d2b856b9` (re-pull with force_repull=true)

## Failing step
`wakeup_environment` → **success** (preview pod came up fine).
`pull_source` / prepare build context → **failed**.

Error (verbatim):
```
prepare build context: update python dependencies: write requirements.txt:
open /tmp/agent-env-...-/app/backend/requirements.txt: no such file or directory
(type: PathError) : no such file or directory (type: Errno)
```

## Root cause
The selected template is `fastapi_react_mongo_shadcn_base_image` (FARM), which requires the backend at `/app/backend/`. During `pull_source`, the deployer stages the preview source into a temp context and runs its "update python dependencies" routine, which opens `/app/backend/requirements.txt` for writing. The open fails with `ENOENT` on the **parent path** — i.e. the `/app/backend/` directory does not exist in the user's preview source. (If only the file were missing it would be created; the failure is the missing directory.)

This is deterministic — reproduced on a clean re-pull — so it is not a transient copy glitch. It is a source-structure problem: the app in the preview environment does not contain a `backend/` directory (with `requirements.txt`) at `/app/backend/`, which this FARM template mandates.

## Why I could not inspect the source directly
The source zip is uploaded only AFTER prepare-build-context succeeds. Since `pull_source` dies before that, no archive exists, so the eph sandbox returns `eph_source_access_failed` on every attempt. Diagnosis is from the step error + the two identical failures.

## Fix (E1 / code)
Restore the expected FARM layout in the app source at `/app`:
- `/app/backend/requirements.txt` (valid pip requirements)
- `/app/backend/server.py` (FastAPI app)
Ensure the backend directory actually exists and is populated at `/app/backend/`. The backend must not be empty, renamed, or located elsewhere. After the structure is corrected, redeploy.

## Not the cause / ruled out
- Not a secret/env issue (fails before write_secrets).
- Not manifest-fixable — this is platform build-context prep running against the user's source layout, before any Dockerfile/nginx manifest is used.
- Not a tier/OOM/infra issue — wakeup_environment succeeded; this is purely the missing backend directory.
